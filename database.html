Introduction to Databases & Persistence Theory

A database is an organized collection of structured information. In scholarly terms, a database solves the Persistence Problem: how to reliably store and retrieve data so that it survives beyond the lifecycle of a single application process.

A. Database Management Systems (DBMS)

Professional engineering distinguishes between two primary categories:

  • Relational (RDBMS): Data organized into tables with predefined schemas (e.g., PostgreSQL, MySQL).
  • Non-Relational (NoSQL): Data stored in flexible formats like documents, graphs, or key-value pairs (e.g., MongoDB, Redis).
The Persistence Gap: Pull

While you could store data in a simple file, databases provide Concurrency Control, Security, Crash Recovery, and Efficient Querying. Without a DBMS, handling millions of simultaneous users would result in catastrophic data corruption.

Schema Design & Table Creation

A Schema is the formal blueprint that defines how data is structured. In SQL, we use DDL (Data Definition Language) to create these structures.

-- Example: Creating a Scholarly Table
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

Basic CRUD Operations: INSERT, SELECT, UPDATE, DELETE

CRUD is the foundation of data manipulation. These operations map directly to DML (Data Manipulation Language) commands.

-- Create, Read, Update, Delete
INSERT INTO users (username) VALUES ('staff_dev');
SELECT * FROM users WHERE id = 1;
UPDATE users SET username = 'lead_dev' WHERE id = 1;
DELETE FROM users WHERE id = 1;

SQL: Relational Algebra & Data Definition

SQL is the declarative implementation of Relational Algebra. Every query is a series of set operations: Selection (σ), Projection (π), and Join (⋈).

Advanced SQL: Analytics, CTEs & Window Functions

Enterprise reporting requires calculating values across sets of rows that are related to the current row without using a traditional GROUP BY clause.

A. Common Table Expressions (CTEs)

CTEs improve query Readability and allow for Recursive Queries (e.g., traversing a threaded comment system or organizational chart).

-- Example: CTE for Recursive Hierarchy
WITH RECURSIVE subordinates AS (
    SELECT id, name, manager_id FROM employees WHERE name = 'CEO'
    UNION ALL
    SELECT e.id, e.name, e.manager_id FROM employees e
    INNER JOIN subordinates s ON s.id = e.manager_id
)
SELECT * FROM subordinates;

B. Window Functions (OVER / PARTITION BY)

// Example: Calculating a running total without grouping
SELECT date, amount,
       SUM(amount) OVER (ORDER BY date) as running_total
FROM sales;

ACID Theory & Transactional Integrity

The ACID model (Atomicity, Consistency, Isolation, Durability) ensures that a database remains in a valid state. Professional mastery focuses on Isolation Levels and the Write-Ahead Log (WAL).

Relational Normalization: Eliminating Anomaly

Normalization (1NF through BCNF) minimizes redundancy. However, staff engineers must decide when to Denormalize for read performance in high-scale systems.

Indexing Architecture & Internal Tuning

Understanding B+ Trees vs. LSM Trees is critical for database tuning. We must also account for internal mechanisms like Buffer Pools and Vacuuming.

Search Engine Theory: Inverted Indexing

B+ Trees are inefficient for full-text search. Scholarly engines like Elasticsearch use an Inverted Index—mapping tokens (words) to the document IDs where they appear.
