Linux Internals & The Shell Workshop

DevOps begins at the operating system level. Linux is the backbone of the cloud, and a scholar must understand its Kernel-space (privileged hardware access) vs. User-space (application execution) architecture.

A. Permissions & The Chmod Strategy

Linux security follows a Discretionary Access Control (DAC) model. Permissions are represented by a 3-digit octal code: User, Group, and Others.

# Example: Setting secure script permissions
chmod 755 deploy.sh # rwx (7) for owner, r-x (5) for group/others
ls -l # Result: -rwxr-xr-x

B. Process Management & Signals

Processes communicate via Signals. A staff engineer uses these to manage service lifecycles without data corruption.

  • SIGTERM (15): Request graceful shutdown. The app should catch this to close DB connections.
  • SIGKILL (9): Forced immediate termination by the kernel.

Docker: OS-Level Virtualization & Container Theory

Docker virtualizes the Software Environment rather than the hardware. Containers share the host kernel while maintaining isolation via Linux Namespaces and Cgroups.

The Union File System (CoW):

Docker images are composed of immutable Layers. Using Copy-on-Write (CoW), only changes are written to a thin top layer, making containers extremely lightweight and fast to start.

A. Multi-stage Builds

# Example: Textbook Multi-stage Build
FROM node:18-alpine AS builder
WORKDIR /app
COPY . .
RUN npm install && npm run build

FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html

Kubernetes (K8s): Distributed Orchestration & Control Planes

Kubernetes is a Distributed Database (Etcd) coupled with Control Loops that continuously reconcile the Actual State with the Desired State.

Staff-Level Insight: The Sidecar Pattern

The Sidecar involves running a secondary container (e.g., a logging agent or service mesh proxy like Envoy) alongside the primary app container in the same Pod. They share localhost and storage, allowing for modular infrastructure concerns.

Continuous Integration & Delivery (CI/CD) Architecture

Scholarly CI/CD focuses on Deployment Frequency and Lead Time. By automating the "Pipeline-as-Code," we ensure that every merge to 'main' is verified and releasable.

# GitHub Actions Workflow (YAML)
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - run: npm test

Jenkins: Enterprise Task Orchestration

Jenkins utilizes a Groovy DSL for complex, multi-branch pipelines. Staff engineers favor Declarative Pipelines for their robustness and error-checking.

Cloud Computing & The AWS Architecture

Built upon the AWS Shared Responsibility Model: AWS manages the physical security, while the customer manages data encryption and OS patching.

Cloud Security: Identity & Access Management (IAM)

In the cloud, identity is the new perimeter. Scholarly security follows the Principle of Least Privilege (PoLP).

A. RBAC vs. ABAC

  • RBAC: Permissions assigned based on job roles (e.g., "Developer" role).
  • ABAC: Permissions based on attributes (e.g., "Allow access if Tag:Project equals X").

Terraform: Infrastructure as Code (IaC) Theory

Terraform uses HCL (HashiCorp Configuration Language) to define infrastructure. A staff engineer knows that the State File is the absolute source of truth.

What is Configuration Drift? Pull

Drift occurs when resources are modified manually in the Cloud Console. Terraform detects this by comparing the state file to the real-world provider and "reconciles" it during apply.

Serverless Mechanics: The FaaS Paradigm

Serverless abstracts the server but introduces Cold Starts—the latency incurred when a provider (like AWS Lambda) initializes a new execution environment.

A. Optimization: Provisioned Concurrency

To eliminate cold starts for enterprise APIs, use Provisioned Concurrency to keep a pool of warm instances ready to respond.
